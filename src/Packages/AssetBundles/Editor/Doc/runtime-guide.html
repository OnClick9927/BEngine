AssetBundle 索引、并发加载与远程更新

InitializeAsync 从内置内容、active/previous 指针和本地 content-addressed cache 选择已验证状态。每个状态只建立一次不可变 AssetBundleCatalogIndex：冻结 address、bundle、每 bundle 资产与预计算 dependency closure。ContainsAddress、GetDependencyClosure 可直接查询，LoadBytes/LoadText 热路径不扫描 catalog；公开索引构造函数会克隆输入，因此调用方之后修改 catalog 不会改变索引。

using BEngine.AssetBundles;

await using var bundles = new AssetBundleManager(new AssetBundleRuntimeOptions
{
    PackageName = "com.example.game",
    CacheDirectory = cachePath,
    BuiltInDirectory = builtInPath,
    RemoteBaseUri = new Uri("https://cdn.example.test/content/"),
    RequireHttps = true,
    MaxRetries = 3
});

await bundles.InitializeAsync(stop.Token);
var plan = await bundles.CheckForUpdatesAsync(stop.Token);
if (plan.HasUpdates)
    await bundles.ApplyUpdateAsync(plan, progress: null, cancellationToken: stop.Token);

await using var text =
    await bundles.LoadTextAsync("Assets/Data/config.json", stop.Token);

AssetBundle Package：构建分组与按包维护

assetbundle package 是构建和维护单元，例如 fonts、images、config。完整 catalog 的 Packages 记录唯一的 bundle 归属与引擎计算的内容指纹；更换整个发布版本号或下载来源不会改变包内容指纹。旧 schema 1–4 和没有显式归属的 catalog 使用隐式 default 包。原有 AssetBundleRuntimeOptions.PackageName 仍标识整个游戏内容发布，不是此次拆分的包名。

运行时通过可选 IAssetBundlePackageManager 接口选择更新或修复范围。加载仍使用全局 address，LoadBytesAsync、LoadTextAsync 和资产引用均不增加包参数。包名不是 address 前缀，跨包重复 address 或 GUID 会被拒绝。

IAssetBundlePackageManager packages = bundles;
// 仅准备配置包及其前向依赖包；其余已安装包保留当前内容。
var configPlan = await packages.CheckPackageForUpdatesAsync("config", stop.Token);
if (configPlan.HasUpdates)
    await packages.ApplyPackageUpdateAsync(configPlan,
        progress: null, cancellationToken: stop.Token);

// 涉及包归属迁移或协调修改时，可以显式选择多个包。
var sharedPlan = await packages.CheckPackagesForUpdatesAsync(
    new[] { "images", "config" }, stop.Token);

// 对当前选中版本进行完整性检查，不擅自升级到最新远程版本。
long downloadBytes = await packages.GetPackageDownloadSizeAsync("config", stop.Token);
await packages.RepairPackageAsync("config",
    progress: null, cancellationToken: stop.Token);

// 读取继续使用全局地址，无需告知该资产所在包。
await using var config = await bundles.LoadTextAsync("Assets/Data/config.json", stop.Token);

按包更新从最新完整远程 catalog 取得目标包，递归纳入 bundle 依赖所属的完整包。下载与激活只处理这个前向闭包；新的本地扁平 catalog 保留未选择包的 bundle、资产和内容版本，不会用整个远程 catalog 替换它们。每个 bundle 的 SourceVersion 保留实际不可变发布来源，因此字体仍在 v1 而配置已在 v2 时，字体修复仍从 v1 获取。服务器需保留客户端仍可能使用的旧不可变发布目录。涉及全局 address 冲突、bundle 移动或引用契约协同变化时，应显式选择相关包一起更新；不会自动反向更新所有使用方。

更新计划是防御性快照，并绑定检查时的 active catalog；另一次更新、回滚或安装改变了基线后，旧包计划会被拒绝，需要重新检查。对象先完成大小与 SHA-256 校验，再原子提交 catalog 和 active 指针，沿用全局 pending 提交与 RollbackAsync 机制。相同内容的包不会因为远端发布号改变而切换版本。删除包内部分资产可正常发布；当前构建器不生成空包，若需要将整个包移除，应使用完整发布更新。

RepairPackageAsync 只修复当前包及其前向依赖闭包中的缺失、截断或 SHA-256 不符对象，保持 catalog 和 active 指针。有效内置内容可在无远程源时修复同 hash 的损坏缓存：通过临时文件复制、回读校验、原子替换完成，网络下载计数为 0。若无法从内置内容修复，则要求持久缓存与可用的远程来源。需要替换的损坏对象仍有加载句柄时会拒绝修复，应先释放句柄；有效旧句柄可继续持有不可变对象。维护期间拒绝新的加载，状态更改由同一状态锁串行执行。

选择将 StreamingAssets 安装到持久目录

工程可在加载任何 AB 之前调用 IAssetBundleLocalInstaller.InstallBuiltInReleaseAsync。传入的不可变发布目录直接包含 version.yaml、catalog 和 bundles/；manager 的 CacheDirectory 可设为 Application.persistentDataPath。此方法会初始化或刷新空 manager，不要求先调用 InitializeAsync。若需要所有读取都来自持久目录，应不配置 BuiltInDirectory 的直接读取回退。

await using var bundles = new AssetBundleManager(new AssetBundleRuntimeOptions
{
    PackageName = "com.example.game",
    CacheDirectory = Application.persistentDataPath
});
var result = await ((IAssetBundleLocalInstaller)bundles).InstallBuiltInReleaseAsync(
    Path.Combine(Application.streamingAssetsPath, "AssetBundles"),
    progress: null, cancellationToken: stop.Token);
// 此后才开始加载包、代码和游戏资产。

每次启动均校验发布 metadata、全部内置 AB 和所选持久对象的大小及 SHA-256；只复制缺失或损坏的对象。复制采用有界异步分块：原生平台最多同时处理 8 个文件，私有流读写在两帧之间继续推进；Web 每次处理 1 个文件，使用按时间片让出的协作路径，不要求工作线程。目标对象按 hash 和大小合并校验，候选版本选择直接复用校验结果。临时文件写完并重新校验后原子替换，最后才替换 active 指针；未改变的指针和 catalog 不重写。取消或任一文件失败时，先收尾已启动的整批 I/O，再返回错误，避免关闭仍在使用的流；不会激活半成品。结果包含复制、复用、修复数量及字节数；进度始终在主线程按 catalog 顺序报告验证、复制、激活与完成。

覆盖安装的新 vN 基线会替换旧版本；同版本但 catalog 已变更时使用新内置发布。有效的更高 vN 远程版本会保留；按包更新生成的有效 IsPackageComposite 本地 catalog 在相同版本号内也会保留，避免重启时覆盖已选择的包组合。损坏但与内置 hash 相同的对象可从内置内容修复。可选远程内容未下载不会强制降级。新本地基线视为已提交；保留原 active 时也保留其 pending 状态。安装使用状态锁，存在已加载或正在加载的 AB 时拒绝安装，安装过程中也拒绝新的 AB 加载。

并发与发布边界

同一 manager 可并发初始化和加载；相同内容 hash 共享一个 bundle task，句柄引用计数决定 UnloadUnused 何时可释放。初始化、Apply、Rollback 与 Cleanup 串行改变状态；加载捕获不可变快照，更新通过发布新状态切换，不原地修改正在读取的 catalog。并发提交相同更新计划只有一次实际激活。

验证、回滚与运行时只读

远程 metadata 与 bundle 均校验大小、SHA-256 和目录边界。bundle 通过 HttpNetworkRequest 流式写 staging 并增量 hash，验证后才移动进 object cache；catalog 和 active/previous 指针使用临时文件原子替换。失败时旧 active 保持可用并清理 .part；Rollback 只切换已验证指针，不重新下载。

运行时是只读消费者：修改 ActiveCatalog 返回值不会改变 manager，不得改写索引、bundle 或 Assets。发布新内容必须经过构建 catalog、Check、下载、验证与原子 Apply。
