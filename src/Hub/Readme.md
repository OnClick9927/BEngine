# BEngine Hub 更新

Hub 的“更新”页通过 GitHub HTTPS API 检查 `OnClick9927/BEngine` 的 `main` 分支，只更新仓库中 `Engine/` 的发行内容。使用者无需安装 Git，也无需下载源码。

也可以只下载一个 `BEngine.Hub.exe` 放进空目录。Hub 不要求预先存在 `BEgine/`、`Packages/` 或 Editor；没有可用引擎时，启动默认进入更新页，“工程”和“引擎与包”页签禁用。禁用页签的文字在深色、浅色主题中保持可读，安装完成后恢复可用。确认后首次安装到自身所在目录，偏好设置也保存在同一安装目录下。

Hub 顶部的“引擎官网”按钮在所有页签都可使用，在系统默认浏览器打开 <https://onclick9927.github.io/BEngine/>。

## 创建与打开工程

“新建工程”需要选择已安装的引擎版本。版本列表在进入创建页时重新扫描，默认采用“引擎与包”中当前选择的版本，也可在创建页切换。没有可用引擎或所选版本的编辑器已被移除时，不能创建工程。

所选版本写入工程的 `Project.yaml`，默认场景中的引擎程序集版本同步匹配。新建完成和以后重新打开工程，都按该记录启动对应版本的编辑器；缺少该版本时提示安装，不会自动改用其他已安装版本。

## 本地版本文档

在“引擎与包”选择引擎版本后，点击“引擎文档”打开该安装版本的本地手册；包的“打开文档”也进入同一阅读器。正文来自当前安装的 `BEgine/BEgine-版本/Editor/Doc` 和 `Packages/包/包-版本/Editor/Doc`，无需访问官网或 GitHub。

阅读器的“引擎手册”和“扩展包”页签共享所选引擎版本。扩展包清单每次刷新都重新扫描当前安装目录，并复用 Hub 的最低引擎版本和包版本选择规则；新增、移除或替换包后，刷新页面或切回页面即可更新入口。没有附带文档的兼容包也会出现在列表中，并标明没有文档。

页面使用与官网一致的配色、字体和组件，支持中英文界面和深浅色切换。深色模式参照编辑器内置 Dark 主题，采用中性灰面板和蓝色交互高亮。首次打开采用 Hub 的语言和主题，阅读器中选择的偏好会保存。正文保留各版本实际随附的语言。文档目录、Markdown、HTML、图片和章节链接都在本地阅读器内打开。

包名和引擎版本名称直接使用安装清单中的原名，不随阅读器语言切换；这些名称也通过 `translate="no"` 标注，避免浏览器自动翻译。文档维护时，API、类名、属性名、文件格式与菜单名保留英文原文，解释和操作说明可以本地化。Markdown 中用行内代码或代码块标注技术名称；HTML 中可使用 `<span translate="no" lang="en">Inspector</span>` 标注正文中的专业术语。阅读器默认保护 `code`、`pre`、`kbd`、`samp`、`var`，并保留作者显式的 `translate="no"` 和有效 `lang` 标注；普通正文和中文提示仍可翻译。

本地文档服务由 Hub 按需启动，关闭 Hub 后停止；阅读期间需保持 Hub 运行。服务只监听本机随机端口，仅提供当前版本的文档目录和内嵌网页资源，不对外提供安装目录文件访问。

Hub 独立于引擎运行时和编辑器：仅打包自身代码、依赖注入及 YAML 支持，不携带图形后端、音频、资源解码器或 Roslyn。Hub、Windows 编辑器和引擎内置 Player 使用共享 .NET 10 运行库；Hub 和编辑器需要 x64 Windows Desktop Runtime，单个 EXE 不再重复携带 .NET。首次缺少兼容运行库时，.NET 原生启动提示会引导下载；已有兼容环境可直接启动。进入 Hub 后，可检测并补充用于项目脚本编译及游戏构建的 .NET 10 SDK，检测通过就复用现有安装。包定义、版本和兼容规则直接复用共享源码；创建工程使用与当前引擎默认工程逐文件核对过的模板。游戏构建仍默认携带运行库，玩家无需预装 .NET。

## 本地数据目录

Hub 和编辑器以 `BEngine.Hub.exe` 所在目录为安装数据根，不依赖当前工作目录或固定盘符。数据按用途保存：

| 位置 | 内容 |
| --- | --- |
| `<工程>/Library/` | 工程资源导入结果、程序集、可复用的编译和 Shader 缓存、工程日志等 |
| `<工程>/Temp/` | 当前工程的素材转换、编译、构建、测试等临时工作文件；活动进程的系统临时目录为 `Temp/System/` |
| `<Hub>/Cache/` | 多工程共用的工具、Android、Gradle、Emscripten、需要解包的 .NET 辅助工具等缓存 |
| `<Hub>/Preferences/` | Hub 工程历史、各版本编辑器偏好、工具配置及独立的 `Codex/` 认证和设置 |
| `<Hub>/Temp/` | Hub 更新下载及事务工作区、未打开工程时的临时文件 |
| `<Hub>/Temp/PlayMode/<公司>/<产品>/` | 编辑器运行工程时的存档和 AB 沙盒；遵循 `Application.persistentDataPath` 的 Play Mode 映射 |

目录由实际使用的功能按需创建，不会因为启动 Hub 就预建 Android、Gradle 或 Emscripten 的目录。已有旧版 `Temp/` 工具缓存会在可安全重命名时迁入 `Cache/`；不覆盖新目录中的同名文件，不移动符号链接或目录联接。新建工程的默认建议位置为同级 `Projects/`。

Hub 使用直接从 EXE 加载的托管单文件包；编辑器将 DLL 和原生库随版本安装，保留脚本编译所需的程序集文件路径。两者启动不再向系统 `%TEMP%/.net` 自解包。进入程序后，仅为自身及工具子进程设置临时目录和共享工具缓存；打开工程后，子进程的系统临时目录跟随该工程。

.NET SDK 与 NuGet 明确复用电脑上已有的环境、默认缓存与用户配置，是允许使用系统用户目录的例外。已有的合法 `DOTNET_CLI_HOME`、`NUGET_*`、`APPDATA`、`LOCALAPPDATA` 自定义设置保持有效，工程与祖先目录中的 `NuGet.Config` 仍按 SDK 原生优先级生效；不再为 Hub 重复下载一套 NuGet 依赖。NuGet 的默认包目录也受 `DOTNET_CLI_HOME` 影响，因此不能把 SDK 主目录单独重定向到 Hub。只会清除从旧版 BEngine 继承、且精确指向本安装旧 `Temp/NuGet`、`Temp/DotNet/Home` 或 `Cache/DotNet/Home` 等隔离目录的环境覆盖。历史 NuGet 副本不会自动批量删除。不修改 Windows 全局环境变量，也不修改构建后游戏的 `Application.persistentDataPath`。

旧用户目录中的已知 BEngine 偏好仍可迁移；历史 .NET、NuGet 或其他应用共用的用户缓存不会自动删除。Codex 使用引擎自己的配置目录，首次使用需要在扩展中登录，原桌面 Codex 的配置和会话不会自动复制。

## 使用流程

1. 打开当前安装目录中的 `BEngine.Hub.exe`，进入左侧“更新”页，点击“检查更新”。
2. 点击检查更新后显示左侧 Git 提交记录和右侧文件变更，可拖动中间分隔条调整宽度。初始状态隐藏提交、文件树和统计区，取消检查后回到初始状态。目录树按“文件 / 大小 / 状态”三列展示；文件与文件夹使用系统图标，新增、修改、删除使用有颜色和形状区别的状态标记。悬停可查看完整路径。
3. 文件总数、新增/修改/删除统计图和下载大小位于右侧文件树下方。检查完成且存在更新内容时才显示“确认下载并安装”，与“检查更新”位于顶部同一行。存在可恢复的下载内容时显示“继续下载并安装”。点击安装后弹窗提示保存工程及关闭相关进程，可以取消；确认后才开始下载。Hub 只下载变化的文件，下载过程中也可以取消，取消后保留更新预览和下载内容。
4. 下载与校验完成后，外部更新器接管，关闭使用当前安装目录的 BEngine 进程，备份、安装、校验并重启 Hub。

界面显示连接、读取文件清单、比较本地文件、下载、校验等阶段及进度；外部更新器继续显示关闭进程、备份、安装和重启进度。

确认下载后隐藏“检查更新”和“确认下载并安装”操作行，取消按钮固定在进度条右侧。检查和下载期间，连接、接收及重试状态与百分比、已下载/总大小合并到固定单行标题；进度条下仅保留一行较小字号的当前路径，长路径省略并可悬停查看完整信息。后台进度每 100ms 合并刷新一次，文件树不会随路径长短移动，也不会重置当前滚动位置或选择。下载失败时保留具体文件、服务器和底层错误，并将完整异常写入 Temp/Logs/HubUpdate.log。

更新页按当前步骤启用操作：初始隐藏安装按钮；检查时显示进度和取消；检查完成且存在更新时提供安装确认，没有更新则隐藏安装按钮；下载时显示下载进度和取消。Git 提交、文件变更和统计区从检查开始显示，取消检查后连同安装按钮一起收起；取消下载保留已经检查到的更新预览。网络等待会持续显示状态，目录响应和文件下载显示接收进度；未知总长度时显示等待动画或已接收字节，不虚构百分比。

提交记录和目录树使用窗口剩余高度，分别滚动。目录树保留独立大小和状态列，长名称使用省略并提供完整路径提示；统计随可用宽度调整，窗口过矮时页面可纵向滚动。

## 安装范围

本地路径根据正在运行的 Hub 位置确定，例如 `<任意目录>/BEngine.Hub.exe` 对应同级 `BEgine/`、`Packages/`。不依赖当前工作目录，不含固定磁盘路径。

更新按文件内容比较，与版本号相同也能检查到变化。检查开始时固定一次远端提交，之后的下载使用同一提交；文件以 Git blob SHA 和长度校验。

下载按 Git blob SHA 和长度合并相同内容：每份内容只传输一次，校验通过后在暂存区复制到所有目标路径，下载大小和进度也按唯一内容统计。全部文件及其分段合计最多 16 个网络请求，超过 64 KiB 的文件最多同时下载 8 份；优先开始大文件，小文件阶段可使用全部 16 个槽位，减少大量小请求的等待。

至少 4 MiB 的文件先下载 64 KiB，确认范围请求可用后将剩余内容分为最多 4 段并行接收，每段使用独立 HTTP/1.1 连接。大小文件的未完成内容均按 Git blob SHA 和长度保存在本次下载工作区；网络中断、取消或关闭 Hub 后，下次从已经写入的偏移继续。分段只记录实际收到的字节，不把预分配空间当成已下载内容。服务器忽略范围请求时安全回退到完整响应。响应范围、长度和最终整文件 Git blob SHA 均通过后才进入安装暂存区；损坏内容会重新下载。

分段请求最多尝试 3 次；仍失败或持续慢速时，进入最多 5 次请求的文件恢复流程，在原下载地址和 GitHub 官方 Git blob API 之间尝试恢复。转换时从保留分段中拼接最长连续前缀，再从缺失位置继续。备用请求仍受总并发约束，每个服务会话最多 16 次，其中 4 次保留给剩余不超过 16 份内容的收尾阶段，并按 API 响应至少预留 10 次请求供元数据检查使用。接口拒绝或限流后停用备用路线，原地址仍可继续有界重试。备用下载同样按固定内容 SHA 和精确范围校验，不使用第三方镜像。

普通请求复用连接并优先协商 HTTP/2，服务器或代理不支持时回退 HTTP/1.1。若连接中断、传输超时或响应提前结束，本次服务会话中同一服务器地址的后续尝试改用 HTTP/1.1，避免重复使用发生故障的多路复用连接；其他服务器不受影响。网络恢复采用有界重试，HTTP 错误和文件校验失败不会触发协议回退。取消或失败后重试，会重新校验同内容组中已完整下载的任一暂存文件，通过后直接复用整组；未完成内容从有效偏移续传。重新检查或重启 Hub 后，同一安装目录、同一远端快照仍会找到原工作区。实际速度取决于网络和 GitHub 服务状态。

`BEgine/` 和 `Packages/` 是受管理的发行目录，远端已删除的文件和本地额外放入的发行文件都会显示在删除清单中。自行添加的引擎版本、包和手工修改也可能被替换，请先看预览。`Preferences/`、`EditorData/` 等用户数据目录，以及发行目录以外的工程和其他本地文件会保留。`Temp/` 不参与远端覆盖，更新成功后单独清理本次更新工作区。

关闭进程时，只处理位于当前安装目录或加载该安装目录 BEngine 模块的 BEngine 进程；其他安装目录的进程不在关闭范围。无法正常退出的相关进程会被终止，因此确认安装前需要保存工作。

## 失败与恢复

首次等待服务器响应最多 30 秒、文件传输空闲最多 20 秒；恢复尝试放宽至响应 60 秒、空闲 40 秒。空闲超时会进入有界重试和连接回退，避免长时间占用下载槽位。持续传输的极慢连接也会保留已收到的内容后尝试恢复，下载过程中可以随时取消。

网络请求有超时，下载错误、取消或校验不通过时不替换已安装文件。单个文件网络重试或校验失败后，其他文件继续下载并保留校验成功的暂存内容，全部结束后汇总失败项；存在失败项时不生成安装计划，再次确认下载只需补齐缺少的内容。已验证文件和未完成分段都会保留，重新检查或重启后可继续。旧版遗留的安全下载工作区也会尝试接管，但其中每个文件仍须通过当前快照的长度与 SHA 校验。用户取消会及时停止全部任务；磁盘写入等本地错误仍立即停止。预览后本地文件发生变化时，更新会停止，要求重新检查。

外部更新器启动成功后 Hub 才会退出。安装先保存备份与恢复记录，失败时尽力回滚；新版 Hub 必须出现稳定的主窗口，才判定重启成功。

同一工作区的下载与安装互斥。回滚后重试同一快照时，先验证当前安装和全部暂存文件，再归档上一轮已结束的安装事务，避免旧备份阻塞重试；未完成的恢复记录仍会阻止安装。只有后续安装完整成功，才清理这些历史恢复材料。

下载、备份、日志及恢复说明固定放在 Hub 所在目录下的 `Temp/HubUpdates/<标识>/`，不再使用系统临时目录。该目录与引擎发行文件隔离，远端文件不能覆盖 `Temp/`。若更新中断，下次启动 Hub 会进入“更新”页，提供“恢复中断的更新”按钮，无需联网即可恢复上一次安装；旧版系统临时目录中的恢复计划也可继续使用。若 Hub 自身已无法启动，可按同一工作目录的 `RECOVERY.txt` 运行外部恢复程序。更新失败时保留工作目录和旧 Temp 内容，直到恢复完成。

新版 Hub 启动验证及安装事务提交成功后，更新器删除本次工作区的下载、暂存和回滚备份，仅保留当前运行中的更新器和少量事务日志。不会遍历清空整个 `Temp/`，因此 Play Mode 数据、活动临时文件及其他未完成更新的恢复内容可以保留；共享缓存与持久设置分别位于 `Cache/` 和 `Preferences/`。清理不跟随符号链接或目录联接；仍被占用的文件会记录到更新日志。

## 发布约定

将源码和重新发布的 `Engine/BEngine.Hub.exe` 一起提交到 `main`。用户更新的是仓库中 `Engine/` 的实际发行文件；仅修改 `src/` 不会发布新的 Hub、引擎或包。
