# BEngine Hub 更新

Hub 的“引擎更新”窗口通过 Git 协议浅拉取 `OnClick9927/BEngine` 的 `main` 分支，稀疏检出仓库中 `Engine/` 的发行内容。包管理也通过 Git 拉取并扫描包目录，两者均不调用 GitHub REST API。
需要可用的 Git for Windows；Hub 优先查找同级 `Tools/Git/cmd/git.exe`，其次查找系统常见 Git 安装位置和 PATH。没有 Git 时会明确提示。
临时仓库仅创建在 `BEngine.Hub.exe` 同级的 `Temp/HubGit/<操作 ID>/` 下；包读取完成即清理预览仓库，包安装、更新、失败或取消后清理本次全部仓库（含依赖）。
引擎检查更新会暂存对应的预览仓库，下载完成并将文件校验、复制到安装暂存区后立即删除该仓库；取消、失败、重新检查或关闭 Hub 时也会清理。更新器仍使用独立的已校验暂存文件执行安装和回滚。

也可以只下载一个 `BEngine.Hub.exe` 放进空目录。Hub 不要求预先存在 `BEgine/`、`Packages/` 或 Editor；没有可用引擎时，启动进入“引擎与包”页，可通过顶部“引擎更新”安装引擎，“工程”页签暂时禁用。确认后首次安装到自身所在目录，偏好设置也保存在同一安装目录下。
侧边栏只保留“工程”“引擎与包”“设置”。“引擎更新”按钮位于“引擎与包”页顶部、“GitHub 包管理”左侧；点击后打开与 Hub 风格一致的独立窗口。关闭窗口时会取消进行中的检查或下载，等待清理 Git 仓库后返回主窗口。

Hub 顶部的“引擎官网”按钮在所有页签都可使用，在系统默认浏览器打开 <https://onclick9927.github.io/BEngine/>。

## 创建与打开工程

“新建工程”需要选择已安装的引擎版本。版本列表在进入创建页时重新扫描，默认采用“引擎与包”中当前选择的版本，也可在创建页切换。没有可用引擎或所选版本的编辑器已被移除时，不能创建工程。

所选版本写入工程的 `Project.yaml`，默认场景中的引擎程序集版本同步匹配。新建完成和以后重新打开工程，都按该记录启动对应版本的编辑器；缺少该版本时提示安装，不会自动改用其他已安装版本。

## 包搜索

“引擎与包”支持按包名、包 ID、运行时或编辑器程序集名称及描述搜索，忽略大小写和首尾空格。
搜索变化后自动定位结果并选中匹配包，完整名称优先于描述中的文字匹配；此前的缩放和拖动不会把新结果留在可见区域之外。
包类型筛选仍然生效，清空关键词可以恢复该类型下的包。搜索时退出单包依赖视图，普通刷新则保留当前视野。

验证入口：`Development/Tools/Test-HubPackageSearch.ps1`；使用 `-InstalledPackagesRoot` 可以逐个验证安装目录中实际包的名称搜索。

## 从 GitHub 管理包

“GitHub 包管理”入口位于主窗口顶部“引擎官网”左侧，仅在“引擎与包”页显示。
管理窗口使用与 Hub 一致的深浅色主题，分为“安装”“更新”“删除”三个页签。
安装时只需粘贴一个 Git 地址，点击“读取 GitHub 包”，再点击“安装全部版本”；无需单独设置分支、子目录或选择版本。
操作按钮统一位于 Git 地址下方：读取成功后才在“读取 GitHub 包”右侧显示“安装全部版本”；读取、安装期间只显示“取消”。
安装成功后隐藏这些操作按钮，修改地址后可重新读取。失败或取消后恢复可用的重试操作。窗口不再提供额外的“关闭”按钮，可通过标题栏关闭。
三个页签的列表按包显示本地版本、远端版本、更新内容和状态，不再提供列表下方的详情文本框；Git 来源地址可通过行提示查看。
检查更新按文件路径、大小及 Git blob SHA 比较内容，区分新增版本、同版本内容更新和保留的本地版本；其他包的提交不会让内容未变的包误报可更新。
更新成功后保留各包的更新内容及“已更新”状态。勾选同一来源中的任意包会同步选择该来源的其他包，仍按整个来源执行安装、更新、删除。
某个来源检查失败时，其他来源的检查结果保留。Git 输出的拉取进度、失败原因会直接显示。
`?path=` 指定子目录，`#` 后指定分支、标签或提交；省略时使用默认分支及仓库根目录。例如：

- `https://github.com/owner/repository.git`：使用默认分支根目录。
- `https://github.com/owner/repository.git?path=/Engine/Packages`：默认分支的指定子目录。
- `https://github.com/owner/repository.git#src`：`src` 分支根目录。
- `https://github.com/owner/repository.git?path=/Engine/Packages#dev`：`dev` 分支的指定子目录。

仍支持 GitHub 网页的 `/tree/分支/目录` 链接。分支名可包含 `/`，路径中的空格或其他特殊字符可以使用 URL 编码。
这些链接用于定位包来源，包内容需符合 BEngine 的 `package.yaml` 格式。
目录按 `Animation/Animation-1.1.0/package.yaml` 这类结构组织；可以包含多个包和多个版本，也可以直接指向某个包含 `package.yaml` 的版本目录。
包身份、版本和最低引擎版本从 `package.yaml` 读取。添加地址表示整个来源目录，其中所有包、所有版本会一起安装。
例如 `?path=/Packages-Exported/ArtImport2D#main` 会安装该目录下的所有 ArtImport2D 版本。
要求较新引擎的版本也可以存入仓库；Hub 在实际展示可用包时仍依据所选引擎版本筛选，不会因此改变工程锁定的版本。
运行时和编辑器的每条 `dependencies` 可通过可选的 `gitUrl` 记录依赖包的完整 Git 地址：

```yaml
runtime:
  assembly: Example.Animation
  rootNamespace: Example
  dependencies:
  - packageId: com.example.rendering
    target: runtime
    gitUrl: https://github.com/example/packages.git?path=/Rendering#main
```

安装时优先使用本次来源或本地已有的兼容依赖；缺失时按 `gitUrl` 读取对应包 ID 的最新兼容版本，并递归补齐它的必需依赖。
自动获取的依赖只安装实际需要的包。同一依赖地址在一次安装中只读取一次，运行时和编辑器对同一依赖的目标会合并检查。
旧清单不必添加此字段；`optional: true` 的缺失依赖不会自动下载。没有可用本地依赖也没有 `gitUrl`、来源中不存在匹配包、目标程序集缺失、循环依赖或下载失败时，整次安装失败并保留原安装。
同一缺失依赖的多处声明应使用一致的 Git 地址。所有主包和新依赖统一校验、发布与回滚。

“更新”页按包展示已安装版本，同一 Git 来源同步选择。“检查更新”在有已安装来源时即可使用，按勾选/选中的来源检查；未选择时检查全部来源。
点击“更新全部版本”会重新读取来源目录，安装新出现的所有版本，并更新已存在版本的内容。
“删除”页选择来源后可以删除该来源的全部本地版本，执行前会确认范围并检查依赖。操作不改动 GitHub 仓库，也不会覆盖引擎自带包的相同 ID 和版本。
Git 拉取期间显示 Git 的实时进度，随后显示文件复制字节、文件数、百分比与校验、安装阶段；操作可以取消。
安装、更新和删除结束后显示持续可见的成功或失败提示。

GitHub 包保存在 `<Hub>/Packages/GitHub/<包 ID>/<版本>/`，每个版本的 `.bengine-github.json` 记录来源、提交和文件清单。
下载以读取时的固定提交为准，文件大小和 Git blob SHA 校验通过后发布；取消、下载失败或校验失败保留原安装，发布失败会回滚。
分支、标签及提交通过 Git 引用解析，支持含 `/` 的分支和 GitHub 网页目录地址。安装使用预览锁定的提交，分支后续变化不会改变本次安装内容。
Git 连续两分钟没有进度时终止；取消会结束对应的 Git 子进程并清理工作目录。
Git 错误日志记录在 `<Hub>/Temp/Logs/HubGitHubPackages.log`。
这部分目录由包管理窗口维护，引擎更新保留其中的文件。当前支持公开仓库，私有仓库认证暂未接入。

验证入口：`Development/Tools/Test-HubGitHubPackages.ps1`，使用真实本地 Git 仓库覆盖分支、标签、固定提交、安装、更新、删除、递归依赖、回滚、窗口、引擎暂存及临时目录清理。

## 包的分发来源

“引擎与包”的包详情及依赖图提示会显示“引擎自带”“外部包”或“来源未记录”。
“引擎自带”表示当前包版本随所选引擎版本分发；同一包的其他版本可以显示为外部包。
包类型、默认启用及必需策略独立于分发来源，工程类型的包也可以是引擎自带包。

导出时根据 `src/Packages` 中实际发布的包生成
`BEgine/BEgine-版本/bundled-packages.json`，记录包 ID、版本和相对于 `Packages` 的清单路径。
Hub 按发行清单匹配，并监控清单变化以更新目录快照。包自己的命名前缀和字段不会授予
“引擎自带”状态。“外部包”表示不属于这次引擎分发，不表示对发布者的认证。
旧引擎缺少清单或清单无法读取时显示“来源未记录”，仍然可以正常使用包。

验证入口：`Development/Tools/Test-HubPackageDistribution.ps1`。

## 本地版本文档

在“引擎与包”选择引擎版本后，点击“引擎文档”打开该安装版本的本地手册；包的“打开文档”也进入同一阅读器。正文来自当前安装的 `BEgine/BEgine-版本/Editor/Doc` 和 `Packages/包/包-版本/Editor/Doc`，无需访问官网或 GitHub。

阅读器的“引擎手册”和“扩展包”页签共享所选引擎版本。扩展包清单每次刷新都重新扫描当前安装目录，并复用 Hub 的最低引擎版本和包版本选择规则；新增、移除或替换包后，刷新页面或切回页面即可更新入口。没有附带文档的兼容包也会出现在列表中，并标明没有文档。

页面使用与官网一致的配色、字体和组件，支持中英文界面和深浅色切换。深色模式参照编辑器内置 Dark 主题，采用中性灰面板和蓝色交互高亮。首次打开采用 Hub 的语言和主题，阅读器中选择的偏好会保存。正文保留各版本实际随附的语言。文档目录、Markdown、HTML、图片和章节链接都在本地阅读器内打开。

包名和引擎版本名称直接使用安装清单中的原名，不随阅读器语言切换；这些名称也通过 `translate="no"` 标注，避免浏览器自动翻译。文档维护时，API、类名、属性名、文件格式与菜单名保留英文原文，解释和操作说明可以本地化。Markdown 中用行内代码或代码块标注技术名称；HTML 中可使用 `<span translate="no" lang="en">Inspector</span>` 标注正文中的专业术语。阅读器默认保护 `code`、`pre`、`kbd`、`samp`、`var`，并保留作者显式的 `translate="no"` 和有效 `lang` 标注；普通正文和中文提示仍可翻译。

本地文档服务由 Hub 按需启动，关闭 Hub 后停止；阅读期间需保持 Hub 运行。服务只监听本机随机端口，仅提供当前版本的文档目录和内嵌网页资源，不对外提供安装目录文件访问。

Hub 独立于引擎运行时和编辑器：仅打包自身代码、依赖注入及 YAML 支持，不携带图形后端、音频、资源解码器或 Roslyn。Hub、Windows 编辑器和引擎内置 Player 使用共享 .NET 10 运行库；Hub 和编辑器需要 x64 Windows Desktop Runtime，单个 EXE 不再重复携带 .NET。首次缺少兼容运行库时，.NET 原生启动提示会引导下载；已有兼容环境可直接启动。进入 Hub 后，可检测并补充用于项目脚本编译及游戏构建的 .NET 10 SDK，检测通过就复用现有安装。包定义、版本和兼容规则直接复用共享源码；创建工程使用与当前引擎默认工程逐文件核对过的模板。游戏构建仍默认携带运行库，玩家无需预装 .NET。

## 本地数据目录

Hub 和编辑器以 `BEngine.Hub.exe` 所在目录为安装数据根，不依赖当前工作目录或固定盘符。数据按用途保存：

| 位置 | 内容 |
| --- | --- |
| `<工程>/Library/` | 工程资源导入结果、程序集、可复用的编译和 Shader 缓存、工程日志等 |
| `<工程>/Temp/` | 当前工程的素材转换、编译、构建、测试等临时工作文件；活动进程的系统临时目录为 `Temp/System/` |
| `<Hub>/Cache/` | 多工程共用的工具、Android、Gradle、Emscripten、需要解包的 .NET 辅助工具等缓存 |
| `<Hub>/Preferences/` | Hub 工程历史、各版本编辑器偏好、工具配置及独立的 `Codex/` 认证和设置 |
| `<Hub>/Temp/` | Hub 更新下载及事务工作区、未打开工程时的临时文件 |
| `<Hub>/Temp/PlayMode/<公司>/<产品>/` | 编辑器运行工程时的存档和 AB 沙盒；遵循 `Application.persistentDataPath` 的 Play Mode 映射 |

目录由实际使用的功能按需创建，不会因为启动 Hub 就预建 Android、Gradle 或 Emscripten 的目录。已有旧版 `Temp/` 工具缓存会在可安全重命名时迁入 `Cache/`；不覆盖新目录中的同名文件，不移动符号链接或目录联接。新建工程的默认建议位置为同级 `Projects/`。

Hub 使用直接从 EXE 加载的托管单文件包；编辑器将 DLL 和原生库随版本安装，保留脚本编译所需的程序集文件路径。两者启动不再向系统 `%TEMP%/.net` 自解包。进入程序后，仅为自身及工具子进程设置临时目录和共享工具缓存；打开工程后，子进程的系统临时目录跟随该工程。

.NET SDK 与 NuGet 明确复用电脑上已有的环境、默认缓存与用户配置，是允许使用系统用户目录的例外。已有的合法 `DOTNET_CLI_HOME`、`NUGET_*`、`APPDATA`、`LOCALAPPDATA` 自定义设置保持有效，工程与祖先目录中的 `NuGet.Config` 仍按 SDK 原生优先级生效；不再为 Hub 重复下载一套 NuGet 依赖。NuGet 的默认包目录也受 `DOTNET_CLI_HOME` 影响，因此不能把 SDK 主目录单独重定向到 Hub。只会清除从旧版 BEngine 继承、且精确指向本安装旧 `Temp/NuGet`、`Temp/DotNet/Home` 或 `Cache/DotNet/Home` 等隔离目录的环境覆盖。历史 NuGet 副本不会自动批量删除。不修改 Windows 全局环境变量，也不修改构建后游戏的 `Application.persistentDataPath`。

旧用户目录中的已知 BEngine 偏好仍可迁移；历史 .NET、NuGet 或其他应用共用的用户缓存不会自动删除。Codex 使用引擎自己的配置目录，首次使用需要在扩展中登录，原桌面 Codex 的配置和会话不会自动复制。

## 使用流程

1. 打开当前安装目录中的 `BEngine.Hub.exe`，进入“引擎与包”页，点击顶部“GitHub 包管理”左侧的“引擎更新”，在弹出的窗口中点击“检查更新”。
2. 点击检查更新后显示左侧 Git 提交记录和右侧文件变更，可拖动中间分隔条调整宽度。初始状态隐藏提交、文件树和统计区，取消检查后回到初始状态。目录树按“文件 / 大小 / 状态”三列展示；文件与文件夹使用系统图标，新增、修改、删除使用有颜色和形状区别的状态标记。悬停可查看完整路径。
3. 文件总数、新增/修改/删除统计图和变更内容大小位于右侧文件树下方。检查完成且存在更新内容时才显示“确认下载并安装”，与“检查更新”位于顶部同一行。存在可恢复的暂存内容时显示“继续下载并安装”。点击安装后弹窗提示保存工程及关闭相关进程，可以取消；确认后从锁定提交的 Git 仓库复制变更文件到安装暂存区，过程中也可以取消。取消后清理 Git 仓库，保留已校验的安装暂存文件供重试。
4. 下载与校验完成后，外部更新器接管，关闭使用当前安装目录的 BEngine 进程，备份、安装、校验并重启 Hub。

界面显示连接、读取文件清单、比较本地文件、下载、校验等阶段及进度；外部更新器继续显示关闭进程、备份、安装和重启进度。

确认下载后隐藏“检查更新”和“确认下载并安装”操作行，取消按钮固定在进度条右侧。检查和下载期间，连接、接收及重试状态与百分比、已下载/总大小合并到固定单行标题；进度条下仅保留一行较小字号的当前路径，长路径省略并可悬停查看完整信息。后台进度每 100ms 合并刷新一次，文件树不会随路径长短移动，也不会重置当前滚动位置或选择。下载失败时保留具体文件、服务器和底层错误，并将完整异常写入 Temp/Logs/HubUpdate.log。

更新窗口按当前步骤启用操作：初始隐藏安装按钮；检查时显示进度和取消；检查完成且存在更新时提供安装确认，没有更新则隐藏安装按钮；下载时显示下载进度和取消。Git 提交、文件变更和统计区从检查开始显示，取消检查后连同安装按钮一起收起；取消下载保留已经检查到的更新预览。网络等待会持续显示状态，目录响应和文件下载显示接收进度；未知总长度时显示等待动画或已接收字节，不虚构百分比。

提交记录和目录树使用窗口剩余高度，分别滚动。目录树保留独立大小和状态列，长名称使用省略并提供完整路径提示；统计随可用宽度调整，窗口过矮时页面可纵向滚动。

## 安装范围

本地路径根据正在运行的 Hub 位置确定，例如 `<任意目录>/BEngine.Hub.exe` 对应同级 `BEgine/`、`Packages/`。不依赖当前工作目录，不含固定磁盘路径。

更新按文件内容比较，与版本号相同也能检查到变化。检查开始时固定一次远端提交，之后的下载使用同一提交；文件以 Git blob SHA 和长度校验。

引擎发行内容通过浅拉取和稀疏检出获取，Git pack 内部负责内容去重。Git 拉取期间展示原生接收、解析和检出进度；随后只把变更文件复制到安装暂存区，并校验文件长度与 Git blob SHA。

相同内容在安装暂存区只复制、校验一份，再复制到所有目标路径；变更大小和复制进度按唯一内容统计。取消或失败时删除对应 Git 仓库，已校验的安装暂存文件可以继续复用。重试时如果需要重新拉取，仍使用预览锁定的提交。

`BEgine/` 和 `Packages/` 是受管理的发行目录，远端已删除的文件和本地额外放入的发行文件都会显示在删除清单中。`Packages/GitHub/` 由 GitHub 包管理维护，引擎更新保留该目录；其他位置自行添加的引擎版本、包和手工修改可能被替换，请先看预览。`Preferences/`、`EditorData/` 等用户数据目录，以及发行目录以外的工程和其他本地文件会保留。`Temp/` 不参与远端覆盖，更新成功后单独清理本次更新工作区。

关闭进程时，只处理位于当前安装目录或加载该安装目录 BEngine 模块的 BEngine 进程；其他安装目录的进程不在关闭范围。无法正常退出的相关进程会被终止，因此确认安装前需要保存工作。

## 失败与恢复

首次等待服务器响应最多 30 秒、文件传输空闲最多 20 秒；恢复尝试放宽至响应 60 秒、空闲 40 秒。空闲超时会进入有界重试和连接回退，避免长时间占用下载槽位。持续传输的极慢连接也会保留已收到的内容后尝试恢复，下载过程中可以随时取消。

Git 传输有停滞超时；拉取、文件复制、校验失败或取消时不会替换已安装文件，并清理对应 Git 仓库。已校验的安装暂存文件可在重试时复用，仍逐个检查长度与 SHA。预览后本地文件发生变化时停止更新，要求重新检查。

外部更新器启动成功后 Hub 才会退出。安装先保存备份与恢复记录，失败时尽力回滚；新版 Hub 必须出现稳定的主窗口，才判定重启成功。

同一工作区的下载与安装互斥。回滚后重试同一快照时，先验证当前安装和全部暂存文件，再归档上一轮已结束的安装事务，避免旧备份阻塞重试；未完成的恢复记录仍会阻止安装。只有后续安装完整成功，才清理这些历史恢复材料。

下载、备份、日志及恢复说明固定放在 Hub 所在目录下的 `Temp/HubUpdates/<标识>/`，不再使用系统临时目录。该目录与引擎发行文件隔离，远端文件不能覆盖 `Temp/`。若更新中断，下次启动 Hub 会进入“引擎与包”并自动弹出更新窗口，提供“恢复中断的更新”按钮，无需联网即可恢复上一次安装；旧版系统临时目录中的恢复计划也可继续使用。若 Hub 自身已无法启动，可按同一工作目录的 `RECOVERY.txt` 运行外部恢复程序。更新失败时保留工作目录和旧 Temp 内容，直到恢复完成。

新版 Hub 启动验证及安装事务提交成功后，更新器删除本次工作区的下载、暂存和回滚备份，仅保留当前运行中的更新器和少量事务日志。不会遍历清空整个 `Temp/`，因此 Play Mode 数据、活动临时文件及其他未完成更新的恢复内容可以保留；共享缓存与持久设置分别位于 `Cache/` 和 `Preferences/`。清理不跟随符号链接或目录联接；仍被占用的文件会记录到更新日志。

## 发布约定

将源码和重新发布的 `Engine/BEngine.Hub.exe` 一起提交到 `main`。用户更新的是仓库中 `Engine/` 的实际发行文件；仅修改 `src/` 不会发布新的 Hub、引擎或包。
