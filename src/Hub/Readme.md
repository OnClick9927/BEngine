# BEngine Hub 更新

Hub 的“更新”页通过 GitHub HTTPS API 检查 `OnClick9927/BEngine` 的 `main` 分支，只更新仓库中 `Engine/` 的发行内容。使用者无需安装 Git，也无需下载源码。

也可以只下载一个 `BEngine.Hub.exe` 放进空目录。Hub 不要求预先存在 `BEgine/`、`Packages/` 或 Editor；没有可用引擎时，启动默认进入更新页，“工程”和“引擎与包”页签禁用。禁用页签的文字在深色、浅色主题中保持可读，安装完成后恢复可用。确认后首次安装到自身所在目录，偏好设置也保存在同一安装目录下。

Hub 顶部的“引擎官网”按钮在所有页签都可使用，在系统默认浏览器打开 <https://onclick9927.github.io/BEngine/>。

Hub 独立于引擎运行时和编辑器：仅打包自身代码、依赖注入及 YAML 支持，不携带图形后端、音频、资源解码器或 Roslyn。Hub、Windows 编辑器和引擎内置 Player 使用共享 .NET 10 运行库；Hub 和编辑器需要 x64 Windows Desktop Runtime，单个 EXE 不再重复携带 .NET。首次缺少兼容运行库时，.NET 原生启动提示会引导下载；已有兼容环境可直接启动。进入 Hub 后，可检测并补充用于项目脚本编译及游戏构建的 .NET 10 SDK，检测通过就复用现有安装。包定义、版本和兼容规则直接复用共享源码；创建工程使用与当前引擎默认工程逐文件核对过的模板。游戏构建仍默认携带运行库，玩家无需预装 .NET。

## 使用流程

1. 打开当前安装目录中的 `BEngine.Hub.exe`，进入左侧“更新”页，点击“检查更新”。
2. 左侧为 Git 提交记录，右侧为文件变更，两个面板始终显示，可拖动中间分隔条调整宽度。目录树按“文件 / 大小 / 状态”三列展示；文件与文件夹使用系统图标，新增、修改、删除使用有颜色和形状区别的状态标记。悬停可查看完整路径。
3. 文件总数、新增/修改/删除统计图和下载大小位于右侧文件树下方。“确认下载并安装”与“检查更新”位于顶部同一行。点击安装后弹窗提示保存工程及关闭相关进程，可以取消；确认后才开始下载。Hub 只下载变化的文件，下载过程中也可以取消，取消后保留更新预览。
4. 下载与校验完成后，外部更新器接管，关闭使用当前安装目录的 BEngine 进程，备份、安装、校验并重启 Hub。

界面显示连接、读取文件清单、比较本地文件、下载、校验等阶段及进度；外部更新器继续显示关闭进程、备份、安装和重启进度。

更新页按当前步骤启用操作：初始安装按钮不可用；检查时显示进度和取消；完成后提供安装确认；下载时显示下载进度和取消。Git 提交和文件变更区域在所有步骤中保持可见，尚无数据时显示空态。网络等待会持续显示状态，目录响应和文件下载显示接收进度；未知总长度时显示等待动画或已接收字节，不虚构百分比。

提交记录和目录树使用窗口剩余高度，分别滚动。目录树保留独立大小和状态列，长名称使用省略并提供完整路径提示；统计随可用宽度调整，窗口过矮时页面可纵向滚动。

## 安装范围

本地路径根据正在运行的 Hub 位置确定，例如 `<任意目录>/BEngine.Hub.exe` 对应同级 `BEgine/`、`Packages/`。不依赖当前工作目录，不含固定磁盘路径。

更新按文件内容比较，与版本号相同也能检查到变化。检查开始时固定一次远端提交，之后的下载使用同一提交；文件以 Git blob SHA 和长度校验。

`BEgine/` 和 `Packages/` 是受管理的发行目录，远端已删除的文件和本地额外放入的发行文件都会显示在删除清单中。自行添加的引擎版本、包和手工修改也可能被替换，请先看预览。`Preferences/`、`EditorData/` 等用户数据目录，以及发行目录以外的工程和其他本地文件会保留。`Temp/` 不参与远端覆盖，更新成功后单独清理旧临时内容。

关闭进程时，只处理位于当前安装目录或加载该安装目录 BEngine 模块的 BEngine 进程；其他安装目录的进程不在关闭范围。无法正常退出的相关进程会被终止，因此确认安装前需要保存工作。

## 失败与恢复

网络请求有超时，下载错误、取消或校验不通过时不替换已安装文件。预览后本地文件发生变化时，更新会停止，要求重新检查。

外部更新器启动成功后 Hub 才会退出。安装先保存备份与恢复记录，失败时尽力回滚；新版 Hub 必须出现稳定的主窗口，才判定重启成功。

下载、备份、日志及恢复说明位于系统临时目录 `BEngine/HubUpdates/<标识>/`。若更新中断，下次启动 Hub 会进入“更新”页，提供“恢复中断的更新”按钮，无需联网即可恢复上一次安装。若 Hub 自身已无法启动，可按同一工作目录的 `RECOVERY.txt` 运行外部恢复程序。更新失败时保留工作目录和旧 Temp 内容，直到恢复完成。

新版 Hub 启动验证及安装事务提交成功后，更新器清理旧 Temp 文件和空目录，也清除本次工作区中的下载、暂存和回滚备份。Temp 路径与编辑器一致：独立 Hub 使用自身目录下的 `Temp/`，名为 `Engine/` 的发行目录使用同级 `Temp/`，源码布局使用工作区外层 `Temp/`。清理保留重启后新建或改写的日志，不跟随符号链接或目录联接；仍被占用的文件会记录到更新日志。当前运行中的更新器和少量事务日志保留在更新工作区。

## 发布约定

将源码和重新发布的 `Engine/BEngine.Hub.exe` 一起提交到 `main`。用户更新的是仓库中 `Engine/` 的实际发行文件；仅修改 `src/` 不会发布新的 Hub、引擎或包。
