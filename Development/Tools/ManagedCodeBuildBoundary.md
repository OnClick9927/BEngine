# 托管代码构建与内容格式的职责

`BEngine.Player.Editor` 提供 `RuntimeManagedCodeReleaseInputCollector` 和 `PlayerManagedCodeBuildPipeline`。输入收集器保留原命名空间与重载，程序集归属从内容包迁至 Core；旧的预编译 Editor 扩展需要重新编译，不增加反向类型转发。它负责项目/包清单、实际 PE 身份与哈希、邻接外部依赖及确定性排序，不解析某种归档格式。

Core 的代码构建管线负责 Release 编译、启动/后续代码输入选择、静态宿主契约、代码与资源可达性的收敛、模块初始化根的延迟激活、裁剪报告，以及原生/预编译 Web 阶段共享程序集的镜像一致性。它复用已有编译器、链接器与平台能力，未增加另一套编译或裁剪实现。

内容提供者通过 `IPlayerManagedCodeResourceGraph` 提供两类能力：根据当前代码和资源收集项目资产闭包；根据当前代码和已选文件筛选资源。筛选接口只返回资源输入，程序集镜像始终由 Core 持有。Core 不知道提供者的包名、归档地址规则或资源编码。

收敛顺序保持为：显式资产根 → 初始资源 → 使用原始程序集执行链接 → 激活本轮实际可达模块 → 资源闭包 → 新资产闭包。资产、资源文件及激活模块都稳定后，采用最终资源结果。不能先用所有代码字面量或所有已安装包初始化根启动，否则死代码和死资源会互相保留。

AssetBundles 的适配器只负责本内容分区的根、资源可达规则、AB 依赖收集及 AOT 资产边界校验。归档、主包/更新包内容、Shader 产物和格式相关报告仍由对应提供者处理。AB 原来的内部选择方法保留为委托入口，仓库内反射测试和调用方同步验证。

验证入口 `Development/Tools/Test-ManagedCodeBuildBoundary.ps1` 不加载 AB 或图形包。它读写真实 PE 与根描述文件，以受控链接进程结果验证收敛、延迟模块激活、失败、取消、静态宿主去重、输入依赖和共享镜像；不把进程夹具当作实际 SDK 链接。实际 Example/Snake Windows/Web 构建和运行另行验收。

尚需继续核对资源可达性分析、Shader 资源策略及其他包的语义边界。通用代码构建的迁移不代表全部包职责已经清理。
