# Asset archive ownership

Core Editor provides the `IBPackageArchiveService` extension contract, its public request/result models and the `BPackageArchive` service facade. Normal engine package discovery, dependency resolution, manifests and compilation remain Core package-manager mechanisms.

EditorWorkbench owns the `.bpackage` asset-authoring workflow: ZIP/manifest interpretation, import planning, conflict and modified-file policy, staging, transactional application/rollback, receipts and default example layout. The five internal implementation types `BPackageImportPlan`, `BPackageImportPlanEntry`, `BPackageImportAction`, `BPackageArchiveFormat` and `BPackagePathUtility` live beside that implementation. They are not public contracts or persisted scene/Prefab/receipt types. Moving them does not require Core type forwarders or changes to resource GUIDs and stored format identities.

Archive-specific path normalization and reserved-name/reparse checks remain shared within this workflow. They call the public platform file/path capabilities. General platform IO and Core service registration are reused; the workbench does not introduce a second filesystem or container. Context export/refresh queries the public active-project capability rather than the private editor bridge.

Independent archive providers can now construct `BPackageImportResult` and `BPackageImportStatus`. Their existing get-only operation-result properties remain unchanged. Constructors reject null required collections (and a null result manifest); they keep the caller-supplied collections/manifest/receipt rather than copying them. Providers retain ownership of those inputs. Mutable import plans and transaction state remain internal to the workbench.

Local Unity 2022.3.62f2c1 exposes `AssetDatabase.ImportPackage` / `ExportPackage` separately from `PackageManager.Client` operations. This informs the distinction between asset archive authoring and engine package resolution; public XML metadata alone does not reveal Unity's native implementation ownership. BEngine's service contract and workflow separation are verified from its own source and binaries.

`Test-PackageArchiveOwnership.ps1` has two consumers: a Core-only provider/facade test without graphics or editor packages, and an installed workbench workflow test. The workflow exercises deterministic output against an actual previous-engine export, v1 import/GUID/receipt compatibility, tracked reimport, conflict policies, path/size/hash/ZIP validation and rollback under an injected file move failure. Reparse rejection is checked through the public filesystem capability with controlled attributes, without requiring privileged OS link creation. Actual Editor smoke separately verifies installed presentation/host startup. Verification outputs belong under the workspace Temp directory.
