Post Processing

包 ID：com.bengine.postprocessing。运行时命名空间：BEngine.PostProcessing。数值基于 Fix64；使用引擎已有的组件、资源、场景和服务接口。

快速开始

  1. 在 Package Manager 启用 Post Processing，检查依赖与 Console 编译结果；导入 ColorVolumes、BloomVignette 示例。

  2. 从 Project 打开示例的 res 场景，在 Hierarchy 检查对象及父子关系。

  3. 同时观察 Scene 与 Game，在 Inspector 检查引用，点击 Play；完成后 Stop，并确认编辑模式资源未被运行时状态污染。

  4. 在输出相机添加 PostProcessLayer，新建全局 Volume 并赋一个 Profile；先仅调整 colorAdjustments.saturation，以便清楚比较开关效果。

  5. 将另一个 Volume 设为局部，设置 center/radius/blendDistance；移动 volumeTrigger 检查过渡，不要只改变渲染相机可见层。

  6. 最后逐个启用 bloom 与 vignette，在明暗区域检查颜色、边缘和开关成本。像素艺术优先保持 bloom 强度为零，再按美术需求增加。

组件与 API

主要类型：PostProcessLayer、PostProcessVolume、PostProcessProfile、ColorAdjustments、Bloom、Vignette、ParameterOverride<T>。

PostProcessLayer 挂在 Camera2D 上，volumeTrigger 默认为相机 Transform，volumeLayer 使用引擎 LayerMask。Volume 的 priority、weight、blendDistance 与 isGlobal 控制叠加。每个效果参数的 value 和 overrideState 分别决定数值及是否参与覆盖。

var layer = camera.gameObject.AddComponent<PostProcessLayer>();
var volume = scene.CreateGameObject("Grade").AddComponent<PostProcessVolume>();
volume.profile = new PostProcessProfile();
volume.profile.colorAdjustments.saturation.value = (Fix64)(-30);
volume.profile.colorAdjustments.saturation.overrideState = true;

代码片段中的 scene、camera、资源和业务对象应来自当前场景。先确认资源加载成功再赋值；不要把资源失败吞掉后继续运行。运行时代码放进项目 runtime/Scripts 对应的 asmdef，编辑器工具放进 Editor 装配。

生命周期与确定性

使用 Awake 获取依赖，Start 初始化首次运行状态。启用较晚的对象仍应在首次 Update 前执行一次 Start。物理操作在 FixedUpdate，普通状态推进在 Update，相机最终跟随在 LateUpdate。通过 BTask 和 BCancellationToken 编排主线程异步流程；退出场景时取消未完成请求并解除事件订阅。

多个 SceneRuntime 应使用 TickAll 共享一次全局帧推进。录制固定输入、固定步长和资源版本后再比较结果；不要使用主机墙上时钟、后台线程或网络返回时刻直接修改模拟状态。视觉与音频的硬件输出不作为确定性逻辑输入。

资源分包与更新

在 AssetImporter 设置 assetBundleName/assetBundleVariant，使用 BuildPipeline.BuildAssetBundles 或播放器构建流程产生目录。跨包序列化引用会加入依赖，公共资源应分配到稳定的共享包，避免重复归属与循环依赖。需要精确构建范围时传入 AssetBundleBuild[]。

首次安装可设置 AssetBundleRuntimeOptions.RequiredBundleNames；null 表示完整安装。通过 IAssetBundleDownloadManager.GetDownloadSizeAsync 估算某组及其依赖的缺失字节，再调用 DownloadDependenciesAsync 获取可选内容。更新目录激活后，已安装可选包继续参与更新。下载完成与目录激活属于不同阶段，失败时不得先切换到不完整资源版本。

本包使用的资源、着色器及其元数据必须随包导出。以相同路径替换内容后检查 BAsset 缓存代次和运行时重新绑定；已有对象持有的资源引用不等于自动替换该对象的所有字段。请在更新成功的明确时机刷新相关资源。

平台与扩展

业务代码通过 FileUtility/PathUtility 调用文件和路径能力；网络功能使用所属包的 IHttpTransport、IWebSocketTransport、ITcpTransport/IUdpTransport 或包自身的服务接口。Windows/.NET 等平台适配器处理实际文件、套接字及硬件；引擎在 Poll 中交付网络结果。扩展平台时替换服务注册，不在组件内直接创建 FileStream、HttpClient、Socket 或 Task。

内置效果包括 Color Adjustments、Bloom、Vignette、Chromatic Aberration、Film Grain、Lens Distortion 和 Color Lookup。为 Post Processing 增加功能时，先查阅 BEngine.PostProcessing 与 BEngine.PostProcessing.Editor 的现有实现、asmdef 依赖与 Editor/Examples。保留 Unity 风格命名及本引擎二维类型；新增公共字段必须具备实际行为，项目效果可通过 PostProcessEffectRegistry.Register<T> 扩展。

行为边界

API 接近 Unity Post Processing Stack 的 Layer/Volume/Profile 模型，不包含完整 URP/HDRP Volume 系统。局部范围是二维圆形，没有任意 Collider 体积。Bloom 是有限采样邻域效果，不是多层 HDR 金字塔。GPU 后端必须支持 RenderTargets 与 SampledTextures；Vulkan 已实现离屏附件、嵌套目标恢复和格式相关管线缓存。

排查顺序

  • 效果不出现：检查 Layer enabled、Volume enabled/weight、层掩码、Profile.active 与参数 overrideState。
  • 游戏变糊：先关闭 Bloom 对比原图；Point 纹理加 PixelPerfectCamera 只能避免采样缩放模糊，不能消除主动添加的后处理扩散。
  • 屏幕全黑：检查平台 RHI 支持和着色器资源打包，验证离屏纹理后再检查最终合成。

遇到异常时记录最小场景、包版本、平台、步长、资源路径和调用顺序。在 Console 保留第一条异常及堆栈；先复现单对象问题，再逐步恢复完整场景。画面问题应同时保存原始分辨率截图与采样配置。

验证清单

  • 对同一场景捕获关闭/启用调色的帧，检查中心像素实际改变且没有黑屏。

  • 局部 Volume 外、边缘和内部各取样，检查权重连续且只影响选中的层。

  • 重复改变窗口尺寸并启用/禁用效果，检查目标尺寸、管线格式和资源释放。

  • 在 Editor Play 和导出的 Windows Player 各运行一次，不以编辑器能加载资源推断包内资源完整。

  • 分别测试冷启动、重复启停、资源更新后重启、失败后重试；记录实际执行的平台，未运行的移动端不能标为通过。

  • 使用固定输入测稳态 Update/Render 的分配与耗时。首次资源解码、着色器编译和缓存预热应单独记录。

编辑器工作流

PostProcessProfile Inspector 按效果分组，提供启用、参数覆盖、范围滑块、颜色选择和保存；PostProcessVolume 可展开内联 Profile 编辑。修改支持撤销，Profile 为共享资源。
