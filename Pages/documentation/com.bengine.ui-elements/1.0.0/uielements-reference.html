UIElements保留模式 UI、UXML/USS、UI Builder、事件调试与运行时控件

UIElements 使用手册

UIElements 是 BEngine 的独立保留模式 UI 包（com.bengine.ui-elements）。它通过 UIDocument 把 VisualElement 树提交到 具有稳定内建身份的 UI Sorting Layer，支持 UXML 结构、USS 样式、UI Builder、HTML 转换、运行时查询与控件事件。

UIDocument 和 VisualElement 使用具有稳定内建身份的 UI Layer；该 Layer 可以重命名和排序， 因此它的连续自然编号会随工程配置变化，不能写死数字。同层仍按 orderInLayer、Hierarchy 和稳定透明顺序排序， 可与使用 UI Layer 的 Particle 穿插。

快速开始

  1. 打开 Window > UIElement > Samples，确认内置编辑器工具可用。
  2. 从 UIElements Examples 导入 Runtime HUD。
  3. 打开 Assets/Examples/RuntimeHud/res/UIElements.scene.yaml。
  4. 选中 Runtime HUD Document；确认 UIDocument.sourceAsset 指向 RuntimeHud.bxml。
  5. 检查 Scale With Screen Size、Reference 1280×720、UI Sorting Layer 与 Sorting Order。
  6. 点击 Play，编辑器会立即聚焦已打开的 Game 窗口；点击 Advance Progress 和 Reset。
  7. 在 Game 选择 16:9、1280×720 等分辨率并展开 Statistics，观察 UI 缩放与批次。
  8. 停止 Play；运行时 Progress、Tree selection 和脚本改值不会写回 UXML/Scene。

UIDocument 组件介绍

字段说明
sourceAssetUXML 或 BEngine UI 资源的工程相对路径；变更后 Reload。
sortingLayer / sortingOrder稳定内建 UI Layer 和层内顺序；Layer 当前编号由工程排序动态确定，可与同层 Particle 穿插。
material / atlas设置 UI 材质与图集，Material + Shader + Atlas 决定合批兼容性。
interactable是否参与运行时指针派发；多个 Document 时优先最高 sortingOrder。
scaleModeConstantPixelSize 或 ScaleWithScreenSize。
referenceWidth / referenceHeight缩放参考分辨率，最小值按运行时保护。

OnEnable 自动 Reload。rootVisualElement 按需实例化；SetVisualTree 可在运行时注入程序化树； DispatchPointerDown 用于明确的指针测试或自定义输入桥。

组件与控件目录

文本与输入

Label、TextField、IntegerField、FloatField、 SearchField、Toggle、Slider、DropdownField、ColorField。

命令与工具栏

Button、Toolbar、ToolbarButton、ToolbarMenu、 ToolbarSearchField、ToolbarSpacer。

容器与数据

VisualElement、Box、Foldout、ScrollView、ListView、 TreeView、TreeViewItem。

展示

Image、ProgressBar。Image 支持 sourcePath/scaleMode； ProgressBar 支持 low/high/value/title。

TreeView

TreeView 支持 items、selection、Expand/Collapse、RefreshItems、ScrollToItem、重命名和拖放。 canRenameItem/validateRename/canStartDrag/canDrop 提供策略钩子；rename 与 drag/drop 有明确事件。 Runtime HUD 用程序化 TreeViewItem 数据演示查询、展开和选择。

UXML 与 USS

<UXML>
  <Style src="RuntimeHud.bss" />
  <VisualElement name="RuntimeHud" class="runtime-hud">
    <Label text="BEngine Runtime HUD" class="hud-title" />
    <ProgressBar name="Progress" low-value="0" high-value="100" />
    <Button name="Advance" text="Advance" />
  </VisualElement>
</UXML>
.runtime-hud {
  width: 520px;
  padding: 18px;
  background-color: #2B2D31F2;
  border-color: #555A63FF;
  border-width: 1px;
}
.hud-title { height: 34px; font-size: 22px; color: #F2F3F5FF; }

USS 支持类、类型和后代选择器，以及宽高、最小尺寸、margin/padding、flex direction/grow/shrink、 align/justify、overflow、font size、color、background、border 等当前 Style 字段。使用相对 Style src 时按 UXML 所在目录解析。

运行时 API 与事件

API用途
root.Q<T> / Query<T>按类型、name、class 查询首项或完整结果。
Add / Insert / Remove / Clear维护保留模式树，自动传播 dirty 状态。
AddToClassList / RemoveFromClassList动态切换 USS class。
styleSheets.Add / ApplyStyleSheets附加并应用 StyleSheet。
SetEnabled / visible控制交互或视觉状态。
SetValueWithoutNotify更新 BaseField 值但避免递归 valueChanged。
RegisterCallback<TEvent>注册 TrickleDown 捕获或默认冒泡事件。
root.Bind(data)按 binding-path 创建可刷新、可释放的双向绑定。
element.schedule.Execute通过 Editor/Player Update 上的 BTaskScheduler 按时间或帧调度。
public override void Start()
{
    var document = GetComponent<UIDocument>();
    var root = document?.rootVisualElement;
    var progress = root?.Q<ProgressBar>("Progress");
    var advance = root?.Q<Button>("Advance");
    if (progress is null || advance is null) return;

    advance.clicked += () => progress.value = Math.Min(100, progress.value + 10);
}

Button 使用 clicked；字段使用 valueChanged；ListView/TreeView 提供 selectionChanged； TreeView 还提供 rename 与 drag/drop 事件。PointerDownEvent、ClickEvent、ChangeEvent 支持捕获/冒泡及 StopPropagation。长期事件、UIBinding 和 ScheduledItem 应在 OnDisable/OnDestroy 释放。

编辑器工作流

  1. 使用 Assets > Create > UI Toolkit > UI Document 创建 UXML； 使用同级 Style Sheet 创建 USS。Project 右键与顶部 Assets 菜单保持一致。
  2. 打开 Window > UIElement > UI Builder，从 Library 搜索控件，在 Hierarchy 维护树，在 UIElement Container Viewport 中选择节点，再通过 Inspector 编辑 identity、binding、class、控件值、布局和颜色。
  3. 使用 New/Open/Save、Undo/Redo、Duplicate/Reorder/Delete、分辨率与缩放工具栏；左右面板和 缩放 Canvas 都可独立滚动。
  4. 在场景 GameObject 添加 UI Toolkit > UI Document，通过 ObjectField/路径指定 sourceAsset。
  5. 设置 UI Layer、Sorting Order、Material、Atlas 与分辨率缩放。
  6. 写 MonoBehaviour，通过 Q 查询具名控件并注册事件。
  7. 打开同组的 Event Debugger，按面板和事件类型筛选，检查回调阶段、传播路径与事件属性。
  8. 打开同组的 Samples，浏览和操作按钮、滚动、开关、文本、列表、数值、颜色和选择字段。
  9. Game 窗口选择多个分辨率，检查文本、长单词、ScrollView 和按钮不重叠。

已有 HTML 可通过 Window > UIElement > HTML Converter 或 Project/Assets 菜单的 Convert HTML to UIElements 转换。转换结果仍需在 UI Builder 中检查布局和当前 USS 支持范围。

如何扩展

组合自定义控件

  1. Runtime asmdef 会自动引用引擎核心中的 UIElements。
  2. 继承 VisualElement 或现有控件，在构造函数中 Add 子节点并设置 class。
  3. 用公开事件暴露语义，而不是让外部依赖内部节点结构。
  4. 程序化创建后通过 UIDocument.SetVisualTree，或在加载 UXML 后把组合控件插入占位节点。
  5. 为材质/图集设置一致值以保留批次兼容性。
public sealed class StatusBadge : VisualElement
{
    private readonly Label label = new();
    public StatusBadge()
    {
        AddToClassList("status-badge");
        Add(label);
    }
    public void SetStatus(string text, bool ok)
    {
        label.text = text;
        if (ok) AddToClassList("ok"); else RemoveFromClassList("ok");
    }
}

当前 UXML 解析器公开支持内置控件集合，没有公开的自定义标签注册 API。 外部自定义控件应以程序化组合或 UXML 占位节点替换实现，不要在文档中宣称未知标签会自动实例化。

编辑器扩展

EditorWindow 可复用 UI Builder/Converter 的 MenuItem 模式；资产创建使用 GenerateUniqueAssetPath 和 AssetDatabase.ImportAsset。自定义 Asset Editor 可提供 UXML/USS 预览，但所有 asset 写入必须在非 Play 状态。

调试与常见问题

只显示空 UI检查 sourceAsset 工程路径、文件存在、UXML 根与 Style src 相对路径。
Q 返回 null检查 name 大小写、控件类型和 Reload 是否已完成。
点击无反应确认 UIDocument.interactable、最高 sortingOrder、Button enabled，且 Game 获得焦点。
不同分辨率溢出使用 ScaleWithScreenSize，设置参考分辨率、min-size、flex 与 ScrollView。
批次过多比较 Material、Shader、Atlas、Sorting Layer/Order 和视觉连续性。
停止 Play 后值恢复运行镜像隔离的预期行为；运行时不能保存 Scene、组件、UXML 或 USS。
