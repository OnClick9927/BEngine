图片导入、纹理压缩与平台覆盖

TextureImporter 支持 PNG、JPEG（.jpg/.jpeg）、BMP、TGA（含 RLE）和 GIF 首帧。JPEG 按 EXIF Orientation 的八种方向归一化为左上原点。图片解码、Inspector 预览、Sprite、图集输入及运行时读取共用 ImageCodec；GIF 动画不作为动画资源导入。PSD/PSB 分层导入属于独立制作功能。

最大源尺寸为每边 16384，单张解码 RGBA8 不超过 256 MiB。Max Texture Size 保持长宽比，Point 使用最近邻，否则使用考虑透明度及 sRGB 的缩放。导入不会改写源图。此流程输出 RGBA8，不保留 HDR/16 位通道、ICC 广色域或多页图片。

压缩格式已写入真实产物：RGBA32、BC1（1 位透明度）、BC3、BC7、ETC2 RGBA8、ASTC 4×4。Automatic 默认使用无损 RGBA32，避免默认导入破坏二维美术；需要压缩时显式选择格式。BC1 对平滑透明度有损，选择 BC3/BC7/ETC2/ASTC 可保留连续透明度。

开启 Generate Mip Maps 后生成到 1×1 的完整 mip 链。Trilinear 在 mip 层间线性混合，Bilinear 在选中的单层内线性采样，Point 使用最近邻。桌面 Vulkan/OpenGL 按设备支持情况直接上传块压缩数据；不支持格式的设备用托管解码器解压全部 mip 层上传 RGBA8。当前 Vulkan 的 Veldrid 后端没有 ASTC 格式映射，因此 ASTC 在该后端回退，占用 RGBA 显存。Windows OpenGL 的 ASTC/ETC2 与 Vulkan 的 ETC2 已在实际 GPU 上验证，移动/Web 仍须目标设备验收。

Inspector 的 Platform Overrides 列表为 Windows、Linux、MacOS、Android、IOS、Web 分别保存 Overridden、Max Texture Size、Format 和 Generate Mip Maps。覆盖只用于 Player/AOT/内容更新构建，编辑器继续使用默认导入设置。AssetBundleBuilder 的 TargetPlatform 参数也可显式选择平台；未指定时使用编辑器产物。构建会检查源文件是否与资源数据库快照一致；文件改变后应先刷新，不能悄悄打包不一致的数据。

导入版本变更通过 AssetImporterVersionAttribute 使旧缓存重新导入。引用由原 meta GUID 和 Sprite local ID 保持；新格式和压缩不会生成新的资源身份。默认无 mip 的 RGBA32 产物继续用 PNG，其他产物使用 BTEX0001（尺寸、格式、各 mip 字节数、SHA-256）。运行时检查完整结构、长度和校验和，既有 PNG 资源仍可读取。

依赖：图片解码使用 StbImageSharp 2.30.16（MIT/Unlicense）；BC 编解码使用 BCnEncoder.Net 2.3.0（MIT）；ETC2/ASTC 托管解码使用 AssetRipper.TextureDecoder 2.6.3（MIT）。ETC2/ASTC 编辑器编码使用 Basis Universal 2.50（Apache-2.0），Windows 工具随引擎导出，其他编辑器宿主可用 BENGINE_BASISU_PATH 指定兼容工具。Player 不调用外部编码程序。

编码使用 UASTC 4×4 level 2，再转码为指定 GPU 格式；逐 mip 编码保留引擎的 sRGB/透明度缩放规则。编辑器编码可取消，每次工具执行有十分钟上限；失败不会提交半成品。纹理仍整张加载，本实现不包含按需 mip 流送、虚拟纹理或 GPU 零拷贝解码。
